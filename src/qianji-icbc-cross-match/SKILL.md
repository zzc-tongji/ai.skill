# 钱迹 × 工商银行 账单交叉匹配

## 应答要求

用户询问用法、或尚未提供必需输入时，给出的说明**必须包含两份账单的获取方法**（见「输入与获取」），再给命令示例；不要只索要文件路径，也不要在用户还没拿到账单时就报错收场。

## 输入与获取

| 账单 | 获取方法 | 产物 |
|---|---|---|
| 钱迹 | APP →「设置 - 账单导出」 | `Qianji_*.xlsx`，首个工作表为账单明细 |
| 工行 | APP 搜索「历史明细打印」→ 选卡片与起止日期 → 发送到邮箱 | 邮件附件 PDF（历史明细电子版） |

### PDF 命名约定

文件名主体必须与钱迹 `账户1` / `账户2` 列中的某个取值**完全相同**。

```
工商银行 信用卡 0114.pdf        ← 对应钱迹账户名「工商银行 信用卡 0114」
工商银行 储蓄卡 3797.pdf        ← 对应钱迹账户名「工商银行 储蓄卡 3797」
```

同一张卡拆成多份时，用 `.1` `.2` `.3` 后缀按时间从早到晚排序，脚本自动合并为一个账户：

```
工商银行 信用卡 0114.1.pdf   ← 2023-12-31 至 2025-10-24
工商银行 信用卡 0114.2.pdf   ← 2025-10-24 至今
```

文件名不含「信用卡」或「储蓄卡」字样的 PDF 会被跳过并提示。两侧文件的列名与取值口径见「版本适配」。

## 前置依赖

```
pip install pdfplumber openpyxl
```

只用这两个库，不 import 任何宿主技能模块，可独立运行。

## 工作流

### 第一步：PDF → xlsx

```bash
python scripts/icbc-pdf-to-xlsx.py --pdf-dir "<工行PDF目录>" --out-dir "<银行xlsx输出目录>"
```

产出每个账户一个 xlsx，外加 `manifest.json`（卡号、账号、行数、分卷来源、警告）。

工行 PDF 带斜向大字号水印（行名 + 下载编号/时间），不过滤会污染单元格——例如把金额 `16.75` 变成 `2-1116.75`。脚本按字号 ≥ 20 过滤，这是提取质量的关键。

五项校验任一不通过即报错退出、不写文件：每页恰好一个表格且表头跨页一致；每页行数等于该页页脚「本页交易笔数」；账户总行数等于各页声明之和；分卷合并后总页数等于 PDF 声明的「共 N 页」；收入/支出金额合计等于页脚算术合计之和。

### 第二步：交叉匹配

```bash
python scripts/cross-match.py \
  --qianji "<钱迹导出.xlsx>" \
  --bank-dir "<第一步的输出目录>" \
  --out "<输出路径>/qianji-icbc-cross-match.<yyyyMMdd.HHmmss>.xlsx"
```

输出写入模板副本，目标已存在时拒绝覆盖；不传 `--out` 则在当前目录生成带时间戳的文件名。模板结构与自定义方式见「模板基线」。

可选参数：`--card-map <json>` 人工指定「账号 → 卡号」覆盖 PDF 页眉提取结果；`--sheet <名称>` 指定数据工作表名；`--template <路径>` 换用其他模板。

## 输出结构

列布局 = `Qianji 操作` + 钱迹原列 + 信用卡区块 + 储蓄卡区块，共 1 + N + M + (K+1) 列。

- **`Qianji 操作`**（最左 A 列）：留空，供人工填写 `Create` / `Delete + Create` 等处理动作。
- **储蓄卡号**：插在储蓄卡区块「账号」之后，账号有值则填入对应卡号（19 位文本，不会科学计数法）。
- 三区块以白 / 浅灰 `F2F2F2` / 中灰 `D9D9D9` 底色区分；全表满边框、自动列宽、冻结首行、微软雅黑 11 号、表头加粗。

### 匹配规则

四条全部满足才视为匹配，并把银行记录并入同一行：

1. **账户**：钱迹 `账户1` 或 `账户2` 等于银行账单的文件名主体（见「PDF 命名约定」）。
2. **时间**：钱迹 `时间` 与银行 `入账日期`（信用卡）/ `交易日期`（储蓄卡）精确到分钟相等，秒数不参与。
3. **收支方向**：钱迹 `类型`=`支出` ⇔ 信用卡 `收支`=`借` ⇔ 储蓄卡金额为负；钱迹 `类型`=`收入` 或 `退款` ⇔ 信用卡 `收支`=`贷` ⇔ 储蓄卡金额非负。
4. **金额**：钱迹 `金额` = 信用卡 `入账金额` = 储蓄卡 `收入/支出金额` 的绝对值。

**账户2 非空时**（转账、还款等）：两个账户都不命中银行账单则跳过匹配；`账户1` 命中按支出情形认领，`账户2` 命中按收入情形认领。

每条银行记录最多被一条钱迹记录认领（一对一消耗），同键多条时取时间最早的，避免一条钱迹记录吃掉多条银行流水。

整表按钱迹 `时间` 升序排列，独立银行行按其自身时间插入最近的钱迹时间下方。

### 配色含义

| 颜色 | 含义 |
|---|---|
| 白 / 浅灰 / 中灰 | 钱迹 / 信用卡 / 储蓄卡区块底色，表示匹配成功 |
| 橙 `FFA500` | 钱迹有、银行账单无 |
| 黄 `FFFF00` | 银行账单有、钱迹无（独立行） |
| 粉 `FFC0CB` | 一对多冲突，**双方都涂粉**：占用列区的那条钱迹行，以及因列区已满而另起一行的银行记录 |
| 蓝字 `0000FF` | 钱迹两个账户都不命中任何银行账单，整行蓝字并跳过匹配 |
| 绿 `92D050` | 人工复核确认。**脚本不生成**，留给使用者复核后手工标注 |

粉色成因：同一行只能容纳一条信用卡记录和一条储蓄卡记录，当一条钱迹记录需要从同一区块认领两条银行记录（例如 `账户1` 和 `账户2` 都是储蓄卡）时，第二条只能另起一行。

## 自动校验

第二步保存后独立回读校验，任一项不通过即删除输出文件并报错退出：列数与表头逐字一致；上述四条件逐行成立（账户按来源反查）；配色与期望状态逐行严格一致；储蓄卡号填充无漏填错填；时间升序；钱迹记录按 `ID` 双向守恒；银行记录双向守恒；全表无缺边框单元格；冻结窗格为 A2。

## 已知情况

**卡号与文件名尾号不符**：脚本从 PDF 页眉提取卡号，末 4 位与文件名尾号不一致时输出 `WARN` 但仍按 PDF 原文填入。应核对 PDF 原件，必要时用 `--card-map` 指定。真实案例：某份文件名标为 `3797` 的账单，页眉卡号末 4 位却是 `1955`，而 `...3797` 那张卡只作为「对方账号」出现在其他流水中——使用者最终选择按文件名口径填 `...3797`。

**信用卡流水出现多个交易卡号**：多币种账户的联名卡会把外币消费记在另一张卡号下（例如主卡 `...0114` 与联名卡 `...8099` 共享额度），脚本输出 `WARN`。属正常业务现象，不影响匹配（匹配按账户名而非卡号）。

解析失败或结果异常，先对照「版本适配」排查。

## 模板基线

`assets/qianji-icbc-cross-match.template.xlsx` 含两个工作表：`交叉比对`（空白数据表，脚本从第 1 行写表头、第 2 行起写数据）和 `图例`（配色说明，脚本原样保留不改动）。写入前会检查数据表确实为空——按「有无非空值」判定，不看 `max_row`/`max_column`，因为 openpyxl 删行清空后维度仍会残留；非空则拒绝写入。

该模板与两个脚本同为**已验证基线**。图例页含 openpyxl 无法用 RGB 表达的主题色填充，重建会丢失。需要自定义时复制一份改副本，再用 `--template` 指定，不要直接改动技能内原件。

## 版本适配（重要）

两个脚本的解析规则基于**特定版本**的输入格式：

- `icbc-pdf-to-xlsx.py` 依赖工行「历史明细（电子版）」PDF 的这些特征——斜向水印字号 ≥ 20（见第一步水印说明）、每页单一表格、页脚含「本页交易笔数 / 本页收入算术合计 / 本页支出算术合计 / 共 N 页 / 第 N 页」、页眉含「卡号」、表头为「入账日期/收支/入账金额」（信用卡）或「交易日期/账号/收入/支出金额」（储蓄卡）。
- `cross-match.py` 依赖钱迹导出的列名 `时间/类型/金额/账户1/账户2/ID`，以及 `类型` 取值为 `支出/收入/退款/转账/还款`。

钱迹或工行改版都可能导致列名对不上、页脚统计缺失、水印特征变化而失败。**若实际使用效果不佳，请复制脚本为副本后修改副本，不要直接改动技能内原件**——保留已验证基线才能在改版时对照定位差异。
